**🇬🇧 [Read in English](README.md)**

Локальный тренажёр по [NeetCode 150](https://neetcode.io/practice), сделанный так, чтобы
проходить его вместе с кодовым агентом — как с **репетитором**, а не как со сборником
готовых ответов.

Все 150 задач лежат на диске в виде Markdown. Один бинарник на Go поднимает локальный сайт,
который помнит, что уже решено, и возвращает задачи на повторение по расширяющемуся
расписанию. Протокол обучения заставляет агента вести вас по задаче подсказка за подсказкой
— и не показывать код, пока вы действительно не попробуете сами.

Протокол — это обычный Markdown в [`AGENTS.md`](AGENTS.md) и
[`tutor/TUTOR.md`](tutor/TUTOR.md), поэтому он работает с любым агентом, который умеет
читать репозиторий. Ничего не привязано к одному вендору.

Решений в этом репозитории нет, и это сделано намеренно. См.
[Чего здесь нет](#чего-здесь-нет).

## Что нужно

- **Go 1.26+** — проверить: `go version`.
- **Кодовый агент** (необязательно) — для режима репетитора. См.
  [Настройка агента](#настройка-агента). CLI и сайт работают и сами по себе.

## Начало работы

```sh
git clone https://github.com/zelfix/neetcode150.git
cd neetcode150

go run ./cmd/nc fetch     # один раз: скачать условия и сигнатуры (несколько минут)
go run ./cmd/nc serve     # http://127.0.0.1:8150
```

В рабочем пространстве есть панель репетитора. При запуске сайта выберите установленный
CLI: `go run ./cmd/nc serve --tutor-provider claude` (по умолчанию) или
`go run ./cmd/nc serve --tutor-provider codex`. Выбранный CLI должен быть установлен и
авторизован. По умолчанию репетитор работает только на чтение; `--tutor-mode full` включает
неограниченный доступ. `--tutor-budget <usd>` задаёт лимит на сессию Claude.

Кнопка **Submit** запускает тесты и начинает обсуждение решения с репетитором. Ответьте в чате:
репетитор сам решит, нужен ли ещё вопрос или уже достаточно данных для оценки. Затем он учтёт
ответы, затраченное время, прошлые попытки и тесты, обновит прогресс и сохранит решение с
отзывом в истории отправок.

`fetch` берёт список задач из
[neetcode-gh/leetcode](https://github.com/neetcode-gh/leetcode), а условия — из публичного
GraphQL API LeetCode, и раскладывает всё в `content/problems/`. Команда идемпотентна:
повторный запуск дозаполняет только отсутствующее и никогда не перезатирает файл, который
вы правили. Семь задач, закрытых подпиской LeetCode Premium, лежат в репозитории — их
условия написаны вручную.

Если не хочется каждый раз писать `go run`, соберите бинарник:

```sh
go build -o nc ./cmd/nc
./nc serve
```

Дальше в этом README подразумевается, что `nc` доступен в `PATH`. Если бинарник вы не
собирали, читайте `nc` как `go run ./cmd/nc`.

## Как решать задачу

```sh
nc next                   # что делать сейчас — сначала повторения, потом новое
nc start two-sum          # создать solutions/0001-two-sum/ и отметить задачу начатой
# ... пишете решение ...
go test ./solutions/0001-two-sum/
nc rate two-sum 4         # как прошло; задаёт дату следующего повторения
```

`nc start` создаёт `solution.go` с официальной сигнатурой на Go и нужными задаче типами
узлов, а рядом — заполненные табличные тесты. Для всех 150 задач в `internal/testbank/cases/`
есть примеры из условия и дополнительные граничные случаи. Проверки учитывают списки,
деревья, графы, последовательности вызовов методов, изменения на месте и разные допустимые
порядки ответа. Для кодеков проверяется восстановление исходных данных без требования
конкретного формата сериализации. Готовых реализаций алгоритмов в банке нет.

`nc tests --all` добавляет эти наборы в уже существующие рабочие папки; `nc tests 128` —
только для одной задачи. Команда сохраняет личные тесты и решения, не начинает попытки и
не меняет прогресс. У ещё не начатых задач тесты появятся по **Start**. В браузерной вкладке
**Tests** видны все тестовые файлы. Свои случаи можно добавлять локально; наборы проверяют
поведение, но не доказывают асимптотическую сложность.

На сайте клик по задаче в списке, на панели или в очереди повторений сразу открывает workspace
с чатом слева: условие — первое сообщение, без запроса к ИИ. К нему можно вернуться
прокруткой вверх. Справа вкладка **My notes** сохраняет заметки автоматически и между
попытками. После завершения чат остаётся доступным для обсуждения идиом Go и
небольших улучшений; оценка и таймер от таких вопросов не меняются. Редактор пустой и выключен, пока вы не нажмёте **Start**. Старое решение можно
раскрыть отдельно; **Start** архивирует его, создаёт чистый каркас и запускает таймер. Уже
начатая попытка открывается с текущим кодом и работающим таймером.
Таймер виден вверху workspace. **Cancel** сохраняет код и останавливает часы; черновик
остаётся в прошлых решениях, а **Start** начинает новую попытку.

## Настройка агента

Инструкции лежат в двух файлах в корне, оба — обычный Markdown:

- **[`AGENTS.md`](AGENTS.md)** — что это за репозиторий, команды, соглашения и одно жёсткое
  правило: не писать решения за пользователя.
- **[`tutor/TUTOR.md`](tutor/TUTOR.md)** — протокол обучения, читается, когда вы просите
  позаниматься с вами.

[`AGENTS.md`](AGENTS.md) — это межинструментальное соглашение, поэтому большинство агентов
подхватывают его вообще без настройки. Для агентов, которые ищут файл со своим именем,
в репозитории уже лежат двухстрочные указатели:

| Ваш агент | Что читает | Настройка |
|---|---|---|
| OpenAI Codex, Cursor, Aider, Zed и другие, принявшие соглашение | `AGENTS.md` | не нужна |
| Claude Code | `CLAUDE.md` → `AGENTS.md` | не нужна — ещё есть команда `/neetcode-tutor` |
| Gemini CLI | `GEMINI.md` → `AGENTS.md` | не нужна |
| GitHub Copilot | `.github/copilot-instructions.md` | не нужна |
| Что-то ещё | — | см. ниже |

Соглашения меняются, так что уточните в документации своего инструмента, какое имя файла он
ждёт, и сошлитесь на `AGENTS.md` одной строкой:

```sh
ln -s AGENTS.md .windsurfrules          # или .clinerules, или как у вас называется
```

А для агента, который вообще не умеет читать инструкции из репозитория, или для обычного
чата — просто вставьте это:

```
Прочитай AGENTS.md и tutor/TUTOR.md в этом репозитории и будь моим репетитором
по следующей задаче. Не пиши решение за меня.
```

## Репетитор

Попросите агента позаниматься с вами — *«что делать дальше?»*, *«дай подсказку»*,
*«посмотри моё решение»* — или запустите `/neetcode-tutor`, если вы в Claude Code.

Главное ограничение в устройстве протокола — агент не должен решать задачу за вас, поэтому
он:

- заставляет пересказать условие своими словами и проверяет границы — пустой вход, один
  элемент, все элементы равны, отрицательные числа;
- требует сначала назвать наивное решение **и его сложность**, потому что паттерн — это
  оптимизация именно наивного решения, а разрыв между его сложностью и ограничениями задачи
  как раз и подсказывает, какой паттерн нужен;
- выдаёт подсказки по одной ступени за раз и никогда не прыгает к концу:

  | Ступень | Что он скажет |
  |---|---|
  | 1 | Название паттерна или намёк, чтобы вы угадали его сами |
  | 2 | Что хранить и какой вопрос это делает дешёвым |
  | 3 | Инвариант — что должно быть верно на каждой итерации |
  | 4 | Псевдокод |
  | 5 | Полное решение на Go с разбором |

- когда тест падает, даёт падающий случай и **один вопрос**, а не готовую правку;
- записывает, до какой ступени пришлось дойти — именно от этого зависит расписание
  повторений.

Если прямо попросить ответ, он сначала предложит следующую ступень — **один раз**.
Попросите снова — даст ответ. Это ваша практика и ваше решение.

Насколько хорошо агент держит эту линию — зависит от агента, и типичный сбой в том, что он
слишком услужлив: сам правит ваш баг или пишет цикл за вас. Если ваш так делает, скажите
*«следуй лестнице подсказок из tutor/TUTOR.md — только одна ступень»*, и он обычно
возвращается в колею.

## CLI

| Команда | Что делает |
|---|---|
| `nc fetch [--force]` | Скачать список задач, условия и сигнатуры на Go |
| `nc serve [--port 8150] [--tutor-provider claude\|codex]` | Поднять сайт и выбрать репетитора |
| `nc user list\|add\|link\|revoke\|rm` | Кто может зайти на сайт, и их ссылки-приглашения |
| `nc next` | Над чем работать сейчас |
| `nc start <задача>` | Создать заготовку решения, теста и заметок |
| `nc status <задача> <состояние>` | `new`, `attempted`, `solved` или `shaky` |
| `nc rate <задача> <1-5>` | Записать, как прошло, и перенести повторение |
| `nc time <задача> <минуты>` | Записать затраченное время |
| `nc review` | Что пора повторить |
| `nc stats` | Прогресс по паттернам и насколько надёжно каждый держится |
| `nc info <задача>` | Пути и состояние одной задачи |

Вместо `<задача>` подойдёт slug, номер с LeetCode, имя каталога или часть названия —
`nc start two-sum`, `nc start 1` и `nc start "valid anag"` работают одинаково.

## Личные данные и SQLite

Прогресс, снимки решений, оценки, память тьютора, заметки, подсказки, журнал и чат
хранятся в `study.sqlite3`. Текущие `solution.go` и тесты остаются обычными файлами.
Завершение попытки сохраняет решение, отзыв и расписание одной транзакцией.
Чат и незавершённая проверка восстанавливаются после перезапуска сервера.

При первом открытии данные из JSON, Markdown и архивов импортируются один раз.
Старые файлы остаются резервной копией и больше не обновляются. Перед первым
переходом остановите старый сервер; `nc migrate` проверяет импорт и целостность базы.

`nc notes <задача>`, `nc hints <задача>` и `nc log` показывают личные записи.
Добавьте `--file <путь>` для замены текста, `nc log --append-file <путь>` для
добавления записи в журнал. Заметки также редактируются в браузере.

Для резервной копии работающей базы используйте
`nc backup study-backup-2026-10-31.sqlite3`: копирование только основного файла
при работающем сервере может потерять данные из WAL. Базу и копии не коммитьте.

## Расписание повторений

Решить один раз — не значит знать. После решения задача попадает на лестницу расширяющихся
интервалов: 1, 3, 7, 16, 35, затем 90 дней, — и `nc rate` двигает по ней. Уверенное
повторение увеличивает интервал, шаткое откатывает в начало. Что пора повторить, видно на
странице **Review**, а `nc next` намеренно ставит повторения выше новых задач.

Лестница — костяк, но не вся картина. У каждой задачи есть ещё *ease*: множитель, который
сжимает интервалы, пока задача продолжает требовать помощи, и растягивает, когда перестаёт.
Две задачи на одной ступени не считаются одинаково надёжными. Кроме того, повторения
сдвигаются на день-два от точной даты — иначе паттерн, пройденный за один присест, вернулся
бы целиком в один день. `nc info` показывает и ease, и фактический интервал.

Оценивайте честно. Шкала — про то, сколько помощи понадобилось, а не про то, как вы себя
чувствуете теперь, когда ответ уже увиден:

| | |
|---|---|
| **1** | Понадобилось полное решение. Вернётся завтра, помечена как шаткая. |
| **2** | Понадобилась сильная подсказка. То же самое. |
| **3** | Дошли сами, но с трудом. Остаётся на лестнице. |
| **4** | Спокойно. Интервал растёт. |
| **5** | Почти мгновенно. Интервал растёт. |

Понадобившаяся подсказка учитывается отдельно, и за расписанием последнее слово именно за
ней: посадка, где был озвучен инвариант (ступень 3), остаётся на своей ступени вместо того
чтобы заработать следующую, а та, где выдали псевдокод или готовый Go (ступени 4 и 5),
откатывается по лестнице вниз. Увидеть ответ — не то же самое, что вспомнить его, как бы
спокойно ни было потом.

Завышенная оценка отправит задачу на 90 дней вперёд — к этому моменту вы её уже забудете.

Поскольку оценка управляет всем расписанием, ошибочную стоит уметь забрать назад:
`nc rate <задача> --amend <1-5>` исправляет последнюю, а `nc rate <задача> --undo` её
удаляет; в обоих случаях расписание пересобирается по оставшимся оценкам. Залогированные
минуты остаются — посадка состоялась, какую бы оценку за неё ни записали.

Повторение — это решение с нуля, а не перечитывание: по протоколу агент не показывает ваше
прежнее решение, пока вы не напишете новое. Самое интересное — сравнить их потом: нашли
что-то лучше или забыли то, что уже знали?

## Coach

Счётчик решённых задач льстит той задаче, которую вы взяли только с подсказкой, — а именно
к ней и стоит вернуться. Страница **Coach** на сайте отвечает на более трудный вопрос,
используя данные, которые оценки уже несут.

Главная цифра — доля задач, последняя посадка по которым прошла вообще без подсказок: не
сколько пройдено, а сколько вы можете сами. Ниже паттерны отранжированы по тому, куда
стоит вернуться: подсказки, падение оценки и низкие оценки поднимают паттерн вверх. Паттерн,
который вы не начинали, в список не попадает — это не слабое место. Паттерн, который
держится, тоже не попадает: список, отмечающий всё, перестают читать. `nc stats` печатает те
же цифры по паттернам в терминале, а `nc weak` называет конкретные задачи.

Страница хранит и то, что знал вывод тестов, но ничто не записывало: какие именно фикстуры
сломал каждый прогон. Со временем это разделяет два разных провала. Сломанный пример из
условия означает, что подход неверен; сломанные только краевые случаи — что подход почти
верен и недотестирован. Прогоны, которые не состоялись (ошибка компиляции, оборванный цикл),
не учитываются, иначе доля удачных прогонов измеряла бы набор текста, а не понимание.

## Чего здесь нет

Две категории файлов намеренно внесены в [`.gitignore`](.gitignore) — там же рядом написано,
почему.

**Чужих решений.** `solutions/`, `study.sqlite3`, её WAL/SHM и старые личные файлы. Клон,
который приходит с 150 готовыми решениями, — это сборник ответов, а задача, которую вы не
продумали, хуже нерешённой: она убирает сигнал о том, что её ещё надо потренировать. Вы
получаете чистый лист и пишете своё.

**Условий задач с LeetCode.** `content/problems/*/problem.md` и `signature.txt` скачиваются
с LeetCode при запуске, а не распространяются вместе с репозиторием. `nc fetch` положит их
на диск за несколько минут. Исключение — семь задач из Premium: LeetCode их не отдаёт,
поэтому их условия написаны с нуля и лежат в репозитории.

Решения не скачиваются тоже. Сайт только ссылается на LeetCode и на разбор NeetCode, но
ничего не встраивает, так что ответ никогда не находится в одном клике от условия.
